Earnify WordPress Plugin: One-Click Mining Roadmap

By Roman Noodles, Founder of Earnify · Updated November 10, 2026

Earnify WordPress plugin roadmap: one-click MinotaurX mining, no code. Earn passive DOGE from visitors. Phased delivery, benchmarks, early access.

For WordPress publishers, integrating browser-based cryptocurrency mining has always demanded a careful dance of code snippets, theme file edits, thread calculations, and wallet formatting. Even a single misplaced script tag can break the experience or silently disable earnings. The Earnify team has heard these frustrations and is preparing a dedicated WordPress plugin that removes every barrier — turning mining setup into an admin panel click, not a code editor chore. This roadmap details exactly what the plugin will deliver, when, and what it means for your bottom line.

The Plugin Vision: No-Code Mining for Every Publisher

Today, Earnify’s miner.js runs entirely in the browser via Web Workers and WASM, relying on a mandatory relay (wss://websocket-stratum-server.com) and the MinotaurX algorithm. The manual integration requires adding a <script> tag and calling earnify.autoMine(wallet, threadPercent). While straightforward for developers, this step stops non-technical site owners from ever trying browser mining.

The WordPress plugin changes that. Instead of pasting snippets, publishers will install the plugin, enter a wallet address, and choose a thread allocation — all from the familiar WordPress admin. The plugin handles script enqueuing, consent management, and miner lifecycle automatically, while preserving every technical guarantee of Earnify’s zero-server architecture.

Key Plugin Facts
• Algorithm: MinotaurX only (no RandomX, Yescrypt, or multi-algo support)
• Relay: All pool traffic flows through the mandatory wss://websocket-stratum-server.com relay — the plugin does not alter this path
• Dev Fee: 1 CPU thread always reserved (effective rate ≈25% on 4‑core machines, ≈14% on 8‑core)
• Payout: Default DOGE (BTC/LTC available via Zpool pool password)
• Data: Zero user data collection, no cookies, no tracking

From Snippet to Settings Panel

Currently, a publisher must add a script like the one below to their theme’s footer.php or use a header/footer snippet plugin. The new plugin eliminates this entirely.

// Manual integration today const script = document.createElement('script'); script.src = 'https://cdn.earnify.cc/miner.js'; script.onload = () => { earnify.autoMine('DQhB...P9px', 50); }; document.head.appendChild(script);

With the plugin, that workflow collapses into a single settings page: wallet address, thread slider (1‑100% of available cores), and a “Save” button. The plugin automatically detects visitor hardware concurrency, respects the always-on dev thread, and starts mining only after an explicit user opt‑in — meeting GDPR obligations out of the box.

MinotaurX Mining, Auto‑Configured

The plugin defaults to Earnify’s recommended pool endpoint (minotaurx.na.mine.zpool.ca:7019, password c=DOGE) and lets publishers switch to EU or SEA endpoints for lower latency based on visitor geography. Because MinotaurX is the only supported algorithm, there is never any confusion about which coin is being mined — every hash contributes directly to DOGE (or BTC/LTC) earnings. According to Earnify’s internal 2025 benchmarks, a typical desktop visitor with 4 cores generates between 1,600 and 2,200 H/s on MinotaurX, translating to roughly 0.5‑1.5 DOGE per thousand visitor‑hours depending on network difficulty.

Phase 1 – One‑Click Activation (Q3 2026)

The MVP will be released as a free, open‑source plugin in the WordPress.org repository. Core features:

  • Zero‑code setup: Install, enter a Dogecoin wallet (or BTC/LTC), set the thread percentage, and save. The miner wakes up on the front end as soon as a visitor consents.
  • GDPR‑ready consent: A simple, customizable banner asks for explicit permission. Rejecting or ignoring the banner means zero mining threads launch.
  • Live visitor opt‑out: A sticky stop() button remains visible during mining so visitors can halt all work instantly.
  • WASM worker lifecycle: The plugin leverages Earnify’s proven miner.js without modification, keeping the same relay path and dev‑fee model.

Because the plugin relies entirely on Earnify’s existing miner core, the performance characteristics remain identical to manual integrations. Expect the same 1/10th to 1/20th of native CPU miner speed, with no SIMD acceleration.

Phase 2 – Advanced Publisher Controls (Q1 2027)

Based on community feedback, Phase 2 will turn the plugin into a comprehensive mining control panel. Planned additions:

  • Per‑page mining rules: Disable mining on sensitive pages (e.g., checkout, login) or boost thread percentage on long‑form content pages.
  • Payout coin selector: A dropdown in settings switches the Zpool password between c=DOGE, c=BTC, and c=LTC without touching any code.
  • Pool region switch: Choose NA (default), EU, or SEA endpoints via radio buttons to reduce latency for geo‑targeted audiences.
  • Session duration caps: Set a maximum mining time per visitor session (e.g., 15 minutes) to balance earnings and user experience.
  • Stats export: Download CSV logs of minotaurxHashrate data (shares accepted, average hashrate) for integration with analytics tools.

All Phase 2 features will be backward‑compatible, so publishers who started with the MVP won’t need to reconfigure anything.

Security & Privacy: No Code, No Data Collection

A common concern with plugins that load third‑party scripts is data leakage. The Earnify WordPress plugin is purposely simple: it enqueues the same open‑source miner.js that anyone can audit on GitHub and passes the publisher’s chosen wallet and thread percentage to the existing autoMine() API. No tracking pixels, cookies, or analytics beacons are ever added. The plugin does not phone home to any Earnify dashboard; all mining proceeds through the mandatory relay to Zpool, exactly as it does in a manual integration.

GDPR Compliance by Design
The plugin bundles an opt‑in consent banner that blocks all Web Worker launches until a visitor clicks “Accept.” A prominent “Stop Mining” button is visible at all times, and the plugin never stores IP addresses, fingerprints, or session data. Publishers can further customize the banner text to match their local privacy policy language.

Because the plugin uses the exact same zero‑server architecture as manual Earnify setups, there is no central server holding mining data. The relay (wss://websocket-stratum-server.com) is a shared, stateless pipe that routes stratum traffic to the pool. Even the relay does not log individual pageviews — it merely forwards hashing work.

Frequently Asked Questions

Does the plugin change Earnify’s dev fee model?

No. The plugin uses the same miner.js core, which always reserves 1 CPU thread for the developer. On a 4‑core machine, that equals an effective 25% fee; on 8 cores it drops to ~14%. The relay and pool path remain identical.

Will the plugin allow mining other coins or algorithms?

Earnify supports only MinotaurX via Zpool. The plugin will let you choose DOGE, BTC, or LTC as the payout currency (using the pool password field), but the algorithm stays MinotaurX. There are no plans for RandomX, Yescrypt, or other algos.

How fast is browser mining compared to native miners?

Earnify’s WASM workers deliver roughly 1/10th to 1/20th of native CPU miner performance because browsers lack SIMD optimizations. A typical 4‑core desktop visitor achieves between 1,600 and 2,200 H/s on MinotaurX, according to Earnify’s internal benchmarks.
